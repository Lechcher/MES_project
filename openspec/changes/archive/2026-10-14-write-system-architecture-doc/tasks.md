## Document Conventions (reference — untracked)

Decisions already made; do not re-litigate during apply:

- **Source of truth:** derive only from `SYSTEM_PROCESS_FLOW-en.md`. Do not use `DATABASE_SCHEMA_EXAMPLE.sql`, `API_CONTACT_SPECIFICATION.md`, `DESIGN.md`, `SYSTEM_PROCESS_FLOW-vi.md`, or the `frontend/`/`backend/` code as inputs.
- **Technology-neutral:** no frameworks, languages, databases, or hosting. Describe logical modules, layers, services, and conceptual runtime only.
- **Reorganize, don't copy:** reframe role/flow material into architecture views; cross-reference rather than restate screen-level process flows.
- **Verbatim codes and values:** ticket state codes, `ACT - ...` badges, leave codes, role names, app aliases (`Jobs`, `Planning`, `Performance`, `Settings`), KPI point values, deadline times, progress milestones, and export formats are copied exactly.
- **Section outline (comprehensive):** Purpose & Scope; System Overview & Context; Architectural Principles; Logical Architecture; Layered View; Module Catalog; Shared Domain Model; Authorization Architecture; Core Engines & Services; Cross-Cutting Concerns & Non-Functional Notes; Integration Points; Extensibility & Future Modules; Glossary of Codes; plus a Traceability mapping.
- **Visual vocabulary:** match the source — ASCII box diagrams, Markdown tables for code registries and the permission matrix, LaTeX for the state-transition and KPI formulas.
- **Language:** English, matching the `-en` source.
