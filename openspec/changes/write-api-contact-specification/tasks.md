## Document Conventions (reference — untracked)

Decisions already made; do not re-litigate during apply:

- **Sources:** derive only from `SYSTEM_PROCESS_FLOW-en.md`, `SYSTEM_ARCHITECTURE.md`, and `DATABASE_SCHEMA_EXAMPLE_OPTIMIZED.sql`. Do not use `DATABASE_SCHEMA_EXAMPLE.sql`, the `*_DIAGRAM.md` files, `DESIGN.md`, `SYSTEM_PROCESS_FLOW-vi.md`, or the `frontend/`/`backend/` skeleton code as inputs.
- **Format:** GraphQL over HTTP, JSON wire format; SDL in ` ```graphql ` blocks, payloads in ` ```json ` blocks, conventions/enums/authorization in Markdown tables. One versioned endpoint.
- **Type mapping:** object/field names `camelCase`; codes as GraphQL `enum` values preserving the exact tokens; `uuid`→`ID`, timestamps→`DateTime`, `jsonb`→`JSON`, `numeric`→`Decimal`. Types mirror the optimized schema's tables and registries.
- **Authorization:** every operation carries role + scope (`All`, `Company-wide`, `Department-only`, `Personal`); preserve the documented asymmetries.
- **No implementation:** no resolvers, no generated schema file, no client code, no SQL. Contract only.
- **Deliverable:** the single root file `API_CONTACT_SPECIFICATION.md`; the three source documents stay unchanged.
- **Section outline (comprehensive):** Purpose & Scope; API Conventions; Authentication & Session; Authorization Model; Type System; App APIs (Jobs, Planning, Performance, Settings & IAM); Shared & Core APIs; Errors; Examples; Traceability.
- **Language:** English.
