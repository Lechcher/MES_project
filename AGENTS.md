# MES Prototype - Agent Guidelines

## App

- **Name**: MES Prototype (project planning, attendance, leave, and performance management)
- **Platform**: Web
- **Directories**:
  - `frontend/` — the web client (Next.js).
  - `backend/` — the API server (Bun + Elysia).

## Design

The visual theme is a dark, data-dashboard interface (dark background, cyan data accent, monospaced KPI numbers). For color palette, component styling, typography, and layout, see [**`DESIGN.md`**](DESIGN.md).

This project uses **shadcn** for UI components (configured in `frontend/components.json`, with primitives under `frontend/src/components/ui/`). **Prefer shadcn components over native TSX/HTML tags**: add components with the shadcn CLI instead of writing raw markup, and compose or extend the existing primitives rather than re-implementing them. Use a native tag only when no shadcn component (or a thin wrapper around one) fits, and keep any such tag styled with Tailwind.

For how the system is put together, read the system documents:

- [`SYSTEM_ARCHITECTURE.md`](SYSTEM_ARCHITECTURE.md) — modules, core engines, shared domain model, authorization.
- [`SYSTEM_PROCESS_FLOW-en.md`](SYSTEM_PROCESS_FLOW-en.md) — roles, screens, and process flows.
- [`API_CONTACT_SPECIFICATION.md`](API_CONTACT_SPECIFICATION.md) — the GraphQL API contract.
- [`DATABASE_SCHEMA_EXAMPLE_OPTIMIZED.sql`](DATABASE_SCHEMA_EXAMPLE_OPTIMIZED.sql) — the reference data schema.

## Rules

### General

- Plan first, then act. Break work into tasks before writing code.
- Use the `openspec` workflow for proposing and implementing changes.
- Keep diffs minimal. Prefer editing existing files over creating new ones.
- Follow the existing conventions and patterns of the codebase.

### Environment Variables

- Write example values in `.env.example` only.
- **Never** read, write, or commit `.env`. It is gitignored.
- Reference configuration through environment variables (for example the auth setup uses `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`).

### Dependencies

- If a new dependency is required, update the **Stack** table above.
- Prefer already-installed packages, the standard library, and native APIs before adding new ones.
- Use the `npm-check-updates` skill to check the newest package versions before adding or upgrading dependencies.
- Verify how to use a package from its source or official documentation before integrating it.

### Code Style

- Biome formats and lints the codebase. Do not add Prettier or ESLint configs.
- Run the formatter from the relevant package (for example `bunx biome check --write` at the root, or `npm run format` inside `frontend/`).
- Import order is handled by Biome's `organizeImports`. Do not add separate import-sort plugins.
- Use TypeScript throughout; keep types explicit at trust boundaries.

### Git

- This repository is developed by both **human developers** and **AI agents**.
- Branch provenance is explicit: humans use `hh/<type>/<description>`; agents use `ai/<agent-name>/<description>`.
- **Never push directly** to a protected branch (`main`, `master`, `production`, `staging`, `release/*`). Push to your own `ai/*` branch and open a Pull Request.
- Merging an `ai/*` branch requires an explicit human approval. No auto-merge, no self-approval.
- AI commits include an AI co-author trailer, for example `Co-authored-by: AI Agent <agent@local>`.
- [**`AGENTS_GIT.md`**](AGENTS_GIT.md) is the single source of truth for Git collaboration; follow it in full.

### Domain Vocabulary

Preserve the shared code tokens verbatim everywhere (UI, API, and data); never rename, translate, or paraphrase them.

- **Ticket state codes:** `REQ`, `ACT`, `PEN`, `APP`, `REJ`, `CAN`, `OVERDUE`.
- **Leave codes:** `AL`, `UAL`, `SL`, `USL`, `PL`, `ML`, `CL`, `EL`, `LWP`, `TOIL`, `VTO`.
